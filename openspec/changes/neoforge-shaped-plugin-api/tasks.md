## 2. Native channel

The two primitives, in order: the native API `ironpumpkin-mods`, which takes the semantics and the catalogue of NeoForge in Pumpkin shape, and the source patches that the modpack build applies. The NeoForge events are Pumpkin events with the NeoForge names, fire sites, fields and cancel and result rules. The foundation (2.1) runs first because every later task tests through a mod linked into an example pack binary. The family tasks (2.2 to 2.18, then 2.25) are ordered by the number of reference modpack mods that need their largest row (in brackets, from `mapping-table.md`), except that a task follows the task it builds on. Each family task implements its delta spec for native mods as modules of `ironpumpkin-mods` and as Pumpkin events.

Every event task has the performance guardrail as a verification line: no evident impact on Pumpkin performance. A fire site checks for registered handlers before it builds the event. `cargo bench -p pumpkin-world` (`noise_generation`, `full_chunk_generation`) and the dispatch bench with zero listeners show no regression outside the bench noise.
